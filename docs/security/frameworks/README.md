# Security Framework Evidence Maps

These documents organize repository evidence using established frameworks without claiming certification or operating effectiveness.

- [`nist-800-53.md`](nist-800-53.md): selected NIST SP 800-53 Rev. 5 control context
- [`mitre-attack.md`](mitre-attack.md): adversary behaviors connected to detections and safeguards
- [`owasp-top-10.md`](owasp-top-10.md): operational controls relevant to cloud-hosted applications
- [`stride.md`](stride.md): repeatable component and trust-boundary analysis
- [`../infrastructure-threat-model.md`](../infrastructure-threat-model.md): STRIDE applied to this repository's infrastructure

## Maintenance rules

- Verify identifiers and names against authoritative framework sources.
- Link only to evidence that exists in the repository or an approved evidence store.
- Distinguish implemented, tested, planned, and not-applicable controls.
- Record uncovered gaps instead of forcing a mapping.
- Revisit maps whenever architecture, paths, detections, or deployment behavior changes.
