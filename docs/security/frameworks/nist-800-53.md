# NIST SP 800-53 Rev. 5 Evidence Map

This working map links repository artifacts to selected NIST SP 800-53 Rev. 5 controls. It does not establish compliance or prove that a control operates effectively in a deployed environment.

Authoritative reference: [NIST SP 800-53 Rev. 5](https://csrc.nist.gov/pubs/sp/800/53/r5/upd1/final).

| Control | Repository evidence | Current implementation |
|---|---|---|
| AC-2 Account Management | `security/policies/aws/` | SCP and IAM permission-boundary examples constrain account and role administration. |
| AC-3 Access Enforcement | `security/policy-as-code/opa/` | OPA policy blocks privileged Kubernetes workload configuration. |
| AC-4 Information Flow Enforcement | `platform/kubernetes/cilium/` | Default-deny network policy establishes an explicit-allow baseline. |
| AC-6 Least Privilege | `security/policies/aws/iam/permission-boundaries/` | Developer permission-boundary policy limits privilege-escalation paths. |
| AU-12 Audit Record Generation | `operations/monitoring/wazuh/` | Wazuh examples ingest host, file-integrity, CloudTrail, and GuardDuty events. |
| CM-2 Baseline Configuration | `infrastructure/ansible/playbooks/` | Versioned Ansible playbooks define repeatable host configuration. |
| CM-6 Configuration Settings | `infrastructure/ansible/` | Hardening tasks cover SSH, PAM, audit, kernel, and filesystem settings. |
| CP-9 System Backup | `operations/` | Gap: backup and tested restoration automation still needs implementation. |
| IA-2 Identification and Authentication | `security/policies/aws/`, `platform/kubernetes/security/` | IAM guardrails and dedicated Kubernetes service-account guidance reduce shared identities. |
| IR-4 Incident Handling | `operations/incident-response/` | Triage, containment, evidence, eradication, and recovery procedures are documented. |
| RA-5 Vulnerability Monitoring and Scanning | `.github/workflows/security_pipeline.yml` | Checkov and Trivy are configured as CI gates. |
| SC-7 Boundary Protection | `platform/kubernetes/cilium/`, `infrastructure/cloudformation/` | Network policies and AWS network templates provide boundary controls. |
| SC-8 Transmission Confidentiality and Integrity | `containers/compose/wazuh-single-node/` | TLS certificates are generated and mounted for Wazuh service communication. |
| SC-28 Protection of Information at Rest | `infrastructure/cloudformation/` | Templates include encryption controls for supported AWS resources. |
| SI-2 Flaw Remediation | `.github/dependabot.yml`, `.github/workflows/security_pipeline.yml` | Dependency updates and vulnerability scans identify remediation work. |
| SR-4 Provenance | `.github/workflows/container-build-sign.yml` | Container images receive signatures and SBOM attestations. |

## Maintenance

- Review quarterly and after material architecture changes.
- Link each claimed control to deployment evidence before treating it as implemented.
- Record exceptions, control owners, test procedures, and last assessment dates separately.
